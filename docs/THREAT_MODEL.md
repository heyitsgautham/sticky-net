# Threat model

This covers the API in `src/`, its outbound calls and the dashboard in `frontend/`.
The evaluation harnesses (`gk-testing/`, `simulated-testing/`, `tester/`, `multi-turn-testing/`) are developer tools that run on a laptop against a local server, so they are out of scope.
[SECURITY.md](../SECURITY.md) lists the controls and how to report a problem.

## What the system does

A caller posts one scammer message per turn to `POST /api/v1/analyze`.
The API classifies it, asks Gemini for a reply in the voice of a believable victim, pulls out the bank accounts, UPI IDs, phone numbers, links and emails the scammer reveals, keeps them per session, and posts the running total to the GUVI evaluator.

## Assets

| Asset | Why it matters |
|---|---|
| `API_KEY` | Lets a caller spend Gemini quota and read session summaries |
| Google service account | Reaches Vertex AI and Firestore for the whole project |
| Extracted intelligence | Real scammer payment details, useful to law enforcement and to the scammer if leaked back |
| Gemini quota and Cloud Run spend | Every turn costs one or two model calls |
| Evaluator score | A non-200 turn or a lost callback costs points |

The persona's own card, bank and Aadhaar details are generated by `src/agents/fake_data.py` and are fake, so they are not assets.

## Actors

| Actor | Access |
|---|---|
| GUVI evaluator | Public `test-api-key`, the analyze routes |
| Scammer | Controls every message text; never holds a key, but the evaluator relays their words |
| Dashboard visitor | The key compiled into the dashboard bundle |
| Anyone on the internet | The Cloud Run URL, `/health`, `/`, `/static`, and the public evaluator key if they look for it |
| Maintainer | Secret Manager, the GCP project and this repository |

## Trust boundaries

```
 internet (evaluator, dashboard, anyone)
        |  HTTPS, x-api-key
        v
 +----------------------------- Cloud Run: sticky-net ----------------------------+
 | MetricsMiddleware > SecurityHeadersMiddleware > APIKeyMiddleware > routes       |
 |   routes -> TurnPipeline -> ScamDetector / HoneypotAgent / IntelligenceExtractor |
 +---------+----------------------+-------------------------+----------------------+
           | ADC                  | ADC                     | HTTPS, fixed URL
           v                      v                         v
     Vertex AI Gemini        Firestore session_state   GUVI callback endpoint
```

1. Internet to API.
   Every byte of the body is attacker-controlled, including `sessionId`, which picks the session state a request reads and writes.
2. API to Gemini.
   Scammer text goes into the prompt, and the model's output comes back as untrusted text.
3. API to Firestore.
   Session state written here comes back on later turns and on other instances.
4. API to the GUVI callback.
   The URL comes from `GUVI_CALLBACK_URL` in settings, never from a request, so a caller cannot point it elsewhere.

## Threats and mitigations

| Threat | Boundary | Mitigation | Residual risk |
|---|---|---|---|
| Guessing `API_KEY` byte by byte through response timing | 1 | `hmac.compare_digest` on every accepted key, no short-circuit | None known |
| Calling the API with the public evaluator key | 1 | `EVALUATOR_API_KEY=` turns the key off; `/metrics` and the key counters show unusual volume | Accepted while the evaluator needs the key |
| Running up Gemini cost with many requests | 1, 2 | 26 second budget per turn, 12 second Gemini timeout, `--max-instances 10` in both deploy scripts, size limits on bodies | No per-client rate limit, see SECURITY.md |
| Exhausting memory with new `sessionId` values | 1 | `BoundedCache` caps each session cache at `SESSION_CACHE_MAX_ENTRIES` | Evicted sessions without Firestore lose their history |
| Reading another session's summary by guessing its `sessionId` | 1 | A key is required, and the evaluator's IDs are UUIDs | A holder of the public key who learns an ID can read that summary |
| Input built to make a regex backtrack, stalling the event loop | 1 | Extraction patterns start a match only where one can begin; a full 101 x 10,000 character history extracts in about 0.1 s | Patterns added later need the same check, which `tests/security/test_regex_performance.py` shows how to write |
| Oversized bodies or deep histories | 1 | 10,000 characters per message, 100 history entries, answered with the 200 fallback | None known |
| Error details leaking paths or credentials | 1 | Fixed error bodies, tracebacks only in logs and Sentry | None known |
| Opening a production deploy with `DEBUG=true` | 1 | Startup fails when `ENVIRONMENT=production` and `DEBUG=true` | `deploy-quick.sh` and `scripts/deploy-manual.sh` set `ENVIRONMENT=production`, but `cloudbuild.yaml` does not, so that path relies on `DEBUG` defaulting to false |
| Prompt injection that makes the persona reveal the system prompt or break character | 2 | The agent has no tools; replies are text only; output parses into `AgentJsonResponse` | The persona can be talked into saying odd things |
| Injected or invented intelligence from the model | 2 | Each bank account, UPI ID, phone, IFSC and name is re-checked by regex validators, plus an independent regex pass over the chat | Links, emails and bank names are kept as the model returned them |
| Keys written to logs or error reports | all | `redact_secrets` structlog processor and Sentry `before_send` scrubbing | Credentials in an unusual format may slip past the patterns |
| Leaked service account key | 2, 3 | Production uses the Cloud Run service account with no key file; `secrets/` is gitignored; gitleaks scans history in CI | A key file a developer creates locally lives outside these controls |
| Vulnerable dependency | all | `uv.lock` and `yarn.lock` pin versions; `pip-audit`, `yarn audit` and Dependabot run on every change or weekly | `yarn audit` fails CI only on critical advisories |
| Clickjacking or MIME sniffing on the API's responses | 1 | `X-Frame-Options: DENY`, `nosniff`, deny-all CSP on JSON routes | The static tester page at `/` has no CSP because it uses inline handlers |

## Logging and detection

Auth rejections log `security_event=auth_failure` with the reason, path and client address, and count in `sticky_net_auth_failures_total`.
Malformed bodies log `security_event=malformed_request` and count in `sticky_net_fallback_replies_total`.
Errors the routes answer with a canned reply still reach Sentry when `ERROR_TRACKING_DSN` is set.

## When to revisit

- When the hackathon ends, set `EVALUATOR_API_KEY=` and rotate `API_KEY`.
- If the API ever accepts traffic that is not the evaluator, add per-key rate limiting before anything else.
- If the agent gains tools or the ability to send messages elsewhere, prompt injection moves from residual to primary risk.
